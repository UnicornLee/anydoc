## 重大发现：Word COM `SaveAs2(wdFormatHTML)` = 图形"截图"银弹

用户问"没办法对这些图形、流程图等进行截图吗？"→ 实测证明**能**，而且比预想的简单得多。

**做法**：`doc.SaveAs2($htmlPath, 8)`（wdFormatHTML=8）。Word 自己把每个图形渲染成独立 PNG 落到 `<name>.files/`。
- 实测 `图表和流程图测试.docx` → 9 张 PNG（`image001..009.png`），≈192 dpi。
- `image009.png`（799×210）实测渲染出「矩形 → 箭头 → 椭圆」流程图，`image006.png` 是 SmartArt 5 布局块 —— 视觉完全正确。
- **HTML 里 `v:shapes` 属性列出该 PNG 包含的形状名**（`矩形_x0020_5 椭圆_x0020_6 直接箭头连接符`），可映射回 Word COM 的 `Shape.Name`（`_x0020_` = 空格转义）。

**顺带验证的 Word COM 坐标能力**（均可作为备选/校验）：
- `Shape.Left/Top/Width/Height` + `Anchor.Information(3)` 页码；
- `InlineShape.Range.Information(3)` 页码 / `(5)` 页内 x / `(6)` 页内 y；
- 类型：`wdInlineShapeChart=12`、`wdInlineShapeSmartArt=15`。

**排除掉的路线（省得再踩）**：
- `Shape.CopyAsPicture()`：PowerShell COM 报 "does not contain a method named 'CopyAsPicture'" → 剪贴板路线不通。
- PDF 中间层 + 裁剪：本机无 `magick`/`mutool`/`pdftoppm`/`gswin64c`，venv 无 `fitz`/`pypdfium2`/`PIL` → 要装外部依赖，不划算。
- 本机 **LibreOffice 已装**（`C:\Program Files\LibreOffice\program\`）。

**另发现 anydoc 当前缺陷**：该文档 3 个浮动 Shape（矩形 5 / 椭圆 6 / 直接箭头连接符 7）**完全没被提取**——`wps:wsp` 浮动形状当前不产生任何 `Inline::Image`。`diagram_blocks` 也只抽 SmartArt 文本不出图。

探测脚本 `probe-word-*.ps1` / `probe-*.ps1` / `probe-html/` / `probe-out.pdf` 已全部清理；根目录残留的 `convert-all-doc_files.ps1`、`convert-one-test.ps1` 也清了（之前 `delete_file` 报成功但实际未删，PowerShell 5.1 ANSI 环境下删除不可靠，**以后用 `cmd /c del` 删**）。

## 跨平台要求确认 + LibreOffice HTML 出图实测

**实测 LibreOffice HTML 导出（方案 E，跨平台可行）**：

```

        --convert-to html --outdir <dir> <src.docx>
```

## 实现完成：跨平台 docx 图形出图（方案 E）

用户拍板：1) E（LibreOffice）2) b（浮动形状合成）3) 转 PNG。**方案 D（Word COM）已弃用**。

### 落地代码

1. **`Cargo.toml`**：加 `image = { version = "0.25", default-features = false, features = ["png", "gif"] }`。
2. **新增 `src/shared/diagram.rs`**（核心）：
   - **关键思路**：LO 无法只渲染文档里某一个图形 → **先把图形隔离**：复制整个 docx，只把 `word/document.xml` 的 `<w:body>` 换成"只含该图形所在段落"的新 body（其余 part 全保留，因为外观和 rels 依赖它们），渲染这个单图文档后**裁白边**即得该图形。
   - `soffice()`：`PATH` （`soffice`/`libreoffice`/`soffice.com`）→ 候选绝对路径（Win `C:\Program Files\LibreOffice\program\soffice.exe`、macOS `/Applications/LibreOffice.app/...`、`/usr/bin/soffice` 等），`OnceLock` 缓存。
   - `drawing_groups()`：扫描 `<w:p`…`</w:p>`（w:p 不嵌套，字符串扫描可靠且保留原始字节），按**段落分组**——同段落的多个浮动形状天然合成一组 → 一张 PNG。
   - `drawing_kind()`：含 `<c:chart` / `<dgm:relIds` → 渲染；含 `<wps:`/`<wpg:` 且**不含** `<a:blip` → 渲染；否则跳过（位图走自己的资产路径）。
   - **映射键用 `wp:docPr/@id`**（不用 name！因为 LO 会重命名：`图示 3`→`形状1`、`矩形 5`→`形状5`）。
   - `DiagramSlot::{Primary, Merged}`：组内第一个 id 出图，其余 `Merged` → 一张组图只输出一次。
   - 一次 `soffice` 调用批量转所有变体（冷启动只付一次）。
   - `crop_white()`：image crate 扫非白像素 bbox，留 2% padding 重编码 PNG。
   - **无图形文档提前 return**，不探测 LO（零开销）。
3. **`src/formats/docx/content.rs`**：`walk_drawing` 在 descr 之后**先查表**——命中则 `Inline::Image`（PNG 资产），未命中才走原 `chart_blocks`/`diagram_blocks` 文本化。**这就是降级：LO 不在场 → 原行为不变**。
4. **`src/formats/docx/mod.rs`**：入口 `render_docx_diagrams(bytes).unwrap_or_default()` 预渲染，`Ctx` 加 `diagrams: &HashMap<String, DiagramSlot>`（`for_part` 一并传递）。

### 踩到的坑

- **LO 会重命名形状**：docx `图示 3`/`矩形 5` → LO HTML `形状1`/`形状5`。**任何靠 name 映射的方案都不可靠**，必须用 `wp:docPr/@id`（或干脆像本方案一样隔离渲染、不映射）。
- `ZipWriter::finish()` 消费 self，之后不能再 `drop(dst)` → 用 `let cursor = dst.finish()?`。
- 变体必须保留原 `<w:sectPr>`，否则页面几何变了、图形尺寸跟着变。
- 整文档 `soffice --convert-to png` **只输出第一页**，不能用来做整页裁剪。
